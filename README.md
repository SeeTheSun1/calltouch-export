# Calltouch → Google Sheets

Скрипт ежедневно в 09:00 по Москве забирает из Calltouch уникально-целевые звонки канала CPC за вчерашний день и дописывает их в Google-таблицу в формате, пригодном для загрузки в Центр конверсий Яндекс Директа.

Запускается автоматически через GitHub Actions, никакой сервер держать не нужно.

---

## Что делает скрипт

1. Запрашивает у Calltouch API звонки за вчера с фильтрами «только уникальные», «только целевые», «только CPC-канал».
2. Хеширует телефон и email клиента алгоритмом MD5 — сырые персональные данные в таблицу не попадают.
3. Проверяет, есть ли уже такие строки в таблице (по всем колонкам сразу), и дописывает в конец только новые.

## Структура таблицы

В Google-таблице один лист с заголовком из 7 колонок:

```
create_date_time | client_ids | emails_md5 | phones_md5 | order_status | revenue | cost
```

`revenue` и `cost` всегда остаются пустыми (под формат Центра конверсий).

## Настройка с нуля

Дальше — пошагово, что нужно сделать **один раз**, чтобы скрипт начал работать в вашей копии репозитория.

### Шаг 1. Скопировать репозиторий себе

В правом верхнем углу страницы репозитория нажать **Fork** → выбрать свой аккаунт. У вас появится копия репозитория с тем же кодом.

### Шаг 2. Получить API-токен Calltouch

1. Войти в личный кабинет Calltouch.
2. Перейти **Интеграции → API**.
3. Скопировать 45-символьный `clientApiId` — это и есть токен.

Также понадобится **ID сайта** в Calltouch. Его видно в URL личного кабинета после `/sites/` — это число, например `12345`.

### Шаг 3. Завести 5 секретов в GitHub

В вашем форке репозитория открыть **Settings → Secrets and variables → Actions → New repository secret** и завести по очереди 5 секретов:

| Имя секрета (вписать ровно так) | Значение | Откуда взять |
|---|---|---|
| `CALLTOUCH_SITE_ID` | например, `12345` | ID сайта в Calltouch |
| `CALLTOUCH_API_TOKEN` | 45-символьный токен | из ЛК Calltouch (Шаг 2) |
| `GOOGLE_SHEET_ID` | строка длиной ~44 символа | пришлём отдельно |
| `GOOGLE_SA_JSON` | целый JSON, начинается с `{` и заканчивается на `}` | пришлём отдельно |
| `ORDER_STATUS` | `ct_static_call` | вписать как есть |

Для `GOOGLE_SA_JSON` важно: скопировать содержимое JSON-файла **целиком** (включая фигурные скобки и переносы строк) и вставить в поле значения секрета.

### Шаг 4. Включить запуск Actions

В форке по умолчанию workflow выключены. Зайти во вкладку **Actions** и нажать «I understand my workflows, go ahead and enable them».

### Шаг 5. Запустить вручную в первый раз

1. Открыть вкладку **Actions** → выбрать workflow **Daily Calltouch Export** в левом меню.
2. Нажать кнопку **Run workflow** справа сверху.
3. Поле «Дата» можно оставить пустым — тогда возьмётся вчерашняя дата. Или указать конкретную дату в формате `DD/MM/YYYY` (например `12/05/2026`).
4. Нажать зелёную кнопку **Run workflow**.

Через 1–2 минуты в списке появится запуск со статусом ✅ (успех) или ❌ (ошибка). Кликнуть на запуск, чтобы увидеть подробности.

### Шаг 6. Проверить результат

1. Открыть Google-таблицу.
2. Внизу должны появиться новые строки за вчерашний день.

Если строк не появилось — открыть логи запуска в **Actions** и посмотреть последнюю строку: она будет вида `пришло X, дублей Y, записано Z`. Если `пришло 0` — значит за выбранный день не было уникально-целевых CPC-звонков (это нормально для дней с низким трафиком).

## Что делать, если запуск упал с ошибкой

Открыть **Actions** → последний запуск → шаг **Run export** → раскрыть лог. Типовые ошибки:

| Сообщение в логе | Что значит | Что сделать |
|---|---|---|
| `HTTP 403` или `Forbidden` от api.calltouch.ru | Неверный токен или ID сайта | Проверить секреты `CALLTOUCH_API_TOKEN` и `CALLTOUCH_SITE_ID` |
| `PermissionError` от Google Sheets | Сервисному аккаунту не дали доступ к таблице | Сообщить нам |
| `GOOGLE_SHEET_ID is required` | Не заполнен один из секретов | Проверить, что все 5 секретов заведены и имена написаны точно как в таблице выше |
| `пришло 0` | За день не было подходящих звонков | Это не ошибка, просто данные отсутствуют |

При непонятной ошибке — прислать нам ссылку на запуск из вкладки Actions, мы разберёмся.

## Запуск за прошлые даты

Если нужно догрузить данные за какой-то конкретный день в прошлом:

1. **Actions** → **Daily Calltouch Export** → **Run workflow**.
2. В поле «Дата» указать нужный день в формате `DD/MM/YYYY`.
3. **Run workflow**.

Повторный запуск за уже выгруженный день дублей не создаст — скрипт сравнит строки и допишет только новое.

## FAQ

**Можно ли изменить время запуска?**
Да: поправить строку `cron:` в `.github/workflows/daily.yml`. Время указывается в UTC.

**Можно ли изменить значение `order_status`?**
Да: поменять секрет `ORDER_STATUS` в Settings → Secrets. Новые записи пойдут с новым значением, старые в таблице не меняются.

**Где хранятся данные?**
Только в Google-таблице, котоаря используется в ЦК директа. На стороне GitHub ничего не сохраняется.
